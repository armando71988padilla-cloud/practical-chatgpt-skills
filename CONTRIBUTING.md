# Contributing

Contributions are welcome when they add a distinct, reusable workflow rather than duplicating an existing skill.

## Principles

- keep `SKILL.md` concise and trigger-focused
- prefer small deterministic scripts only when they materially improve reliability
- do not include secrets, private logs, private infrastructure details, or copied proprietary material
- do not include obfuscated code or hidden downloads
- make risky behavior explicit
- keep examples fictional and generic
- test helper scripts before submission

## Pull request checklist

- explain the problem the skill solves
- show at least three realistic trigger examples
- describe expected output
- state whether the skill needs connectors, code execution, network access, or mutation
- validate the skill package
- add or update public tests
