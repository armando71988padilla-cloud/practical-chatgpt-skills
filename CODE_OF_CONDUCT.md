# Code of Conduct

This project exists to help people build and troubleshoot software more safely.

## Be constructive

- Be respectful and assume good faith.
- Critique code, designs, and ideas without attacking people.
- Keep bug reports and reviews specific enough to act on.
- Help less-experienced contributors without talking down to them.

## Protect people and private data

- Do not post credentials, tokens, private infrastructure, personal information, or sensitive logs.
- Do not dox, harass, threaten, or target contributors or users.
- Report security vulnerabilities through GitHub Private Vulnerability Reporting instead of public Issues.

## Keep contributions trustworthy

- Do not hide network access, mutation, privilege use, or executable behavior.
- Do not submit obfuscated or intentionally deceptive code.
- Do not knowingly present unverified security claims as proven facts.
- Public examples and fixtures should use generic or fictional data.

## Maintainer action

Maintainers may edit, hide, lock, or remove content that violates these expectations and may restrict participation when necessary to protect the project or its community.

The goal is not ceremony. It is a useful, technically honest project where people can safely ask questions, report problems, and contribute improvements.
